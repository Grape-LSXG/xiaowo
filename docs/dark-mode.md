# 深色模式

## 三种模式

| 模式 | 行为 |
|---|---|
| 跟随环境光（默认） | 环境光 < 20 lux 切深色，> 120 lux 切浅色，中间保持不动 |
| 始终浅色 | 固定粉紫浅色 |
| 始终深色 | 固定深色 |

入口：两个 App 的「我」页 → `🌗 外观`。

## 为什么用环境光而不是只按时间

用户要的是"根据环境光亮暗自动切换"，所以主判据是 `TYPE_LIGHT` 传感器。
但传感器不是所有设备都有、休眠时也可能不回调，所以叠了一层时间兜底
（19:00–7:00 视为暗）。

用的是**滞回判断**，不是直接比较：

```
lux < 20  且当前是浅色  → 切深色
lux > 120 且当前是深色  → 切浅色
其余情况               → 不动
```

两个阈值分开是为了防抖 —— 用单一阈值的话，手一挥屏幕就闪一下。
另外 `SensorEventListener` 回调可能很密集，做了 3 秒限流，
因为一次切换要 `recreate()` 整个 Activity。

## 实现方式：在工厂层做颜色映射

**没有逐屏写两套 UI。** 全部界面画颜色都经过 `Ui.round / Ui.gradient /
Ui.tv / Ui.pill`，所以在这几个入口统一调 `Theme.adapt(color)`，
一次覆盖全部 **204 处硬编码色**。

具体分三类：

1. **语义令牌**（`Ui.BG` 等）从 `final` 改成可变，`Ui.applyTheme()` 在换主题时
   把它们的值刷成当前主题的取值。代价是不能写进 `switch-case`（实际没这么用过）。
2. **硬编码字面量** 由 `Theme.adapt()` 在工厂里逐色映射。
3. **绕过工厂的 8 处**（3 个 `setBackgroundColor` + 5 个 `setTextColor`）
   单独包了 `Theme.adapt()`。

## 颜色映射规则

按亮度分三档，阈值 **0xB0 是量出来的**：

项目里所有"文字/彩色"字面量亮度最高到 `0x9C`（`0xFF3ECF8E` 浅绿），
所有"底色"字面量亮度最低从 `0xC7`（`0xFFC9C4D4` 浅灰）起 ——
中间有 **43 级空档**，所以 0xB0 放哪边都不会误判。

| 亮度 | 判定 | 映射 |
|---|---|---|
| ≥ 0xF5 | 近白底 | `0xFF1E1B28` 卡片色 |
| ≥ 0xB0 且灰 | 浅灰底 | `0xFF262232` 提亮层 |
| ≥ 0xB0 且彩色 | 浅彩色底 | `tintDark`：压到 ~16% 并保留色相 |
| < 0xB0 灰，≥ 0x80 | 弱文字 | `0xFF8D8599` |
| < 0xB0 灰，≥ 0x50 | 次要文字 | `0xFFB9B2C8` |
| < 0xB0 灰，< 0x50 | 主文字 | `0xFFF2EEF8` |
| < 0xB0 彩色 | 彩色 | `tintLight`：向白混合 34% |

半透明深色（`0x14000000` 分隔线）翻成 `0x14FFFFFF`。

## 两个靠肉眼发现不了的 bug

写完之后用脚本验算对比度，抓出来两个：

**1. 主文字被当成"分隔线"**

原来的规则是 `r,g,b 都 < 0x60` 就翻成半透明白，
没检查 alpha。主文字 `0xFF1E1B2E` 满足这个条件（虽然它不透明），
结果正文变成一条半透明白 —— 深色模式下文字直接没了。

修法：规则加 `a < 0xFF`。

**2. 彩色被提亮成洋红/青**

原来是逐通道乘 1.55。问题在于本来饱和的通道先撞顶：
粉 `0xFFEC4899` 的 R/B 都顶到 255，变成洋红 `0xFFFF83FF`；
绿会变青。色相全跑了。

修法：改成**向白色线性混合**（等价于降饱和、提亮度），色相基本不动：

```java
int nr = (int) (r + (255 - r) * 0.34f);
```

改完实测：粉 → `0xFFF286BB`，绿 → `0xFF65C287`，色相正常。

## 对比度验算（WCAG AA）

深色卡片底 `0xFF1E1B28` 上，**16/16 全部达标，最低 4.79:1**：

| 用途 | 深色值 | 对比度 |
|---|---|---|
| 主文字 | `0xFFF2EEF8` | 14.78 |
| 次要文字 | `0xFFB9B2C8` | 8.26 |
| 弱文字 | `0xFF8D8599` | 4.79 |
| 主色紫 | `0xFF9E80E3` | 5.35 |
| 强调粉 | `0xFFF286BB` | 7.16 |
| 成功绿 | `0xFF65C287` | 7.74 |
| 错误红 | `0xFFE76F6F` | 5.55 |
| 星星橙 | `0xFFCD8D5C` | 6.08 |

## 真机像素验证

不靠"看着像"，直接截屏采样像素：

| 区域 | 深色模式 | 浅色模式 |
|---|---|---|
| 页面背景 | `#14121A` | `#FCF7FA` |
| 侧栏 / 卡片 | `#1E1B27` | `#FFFFFF` |
| 顶部渐变 | `#252231` | `#F0EBFD` |

亮度从 19–36 跳到 238–255，三层（背景 / 卡片 / 渐变）都正确分层。

顺带验证了环境光判定是真实生效的：读取传感器得到 `0 lux`（当时手机朝向暗处），
系统据此判定为"暗"，Auto 模式切深色 —— 这是正确行为，不是 bug。

## 换主题时的性能考虑

切换要 `recreate()` 整个 Activity。原因：界面是纯代码搭的，
逐控件改色既容易漏、也很难做过渡，重建最稳。

为此有两条约束：

- `Lux.isBright()` 最多阻塞 900ms，**必须放后台线程**（这条是查代码时发现并修掉的）。
- 传感器回调做了 3 秒限流，避免连续 `recreate()`。

## v2.4/v2.5 修复：三个真机才暴露的 bug

第一版上线后用户反馈了三件事，根因其实是**两个**：

### 一、卡片变浅色 + 文字消失（同一个根因）

现象：切深色后卡片还是白的，文字几乎看不见。

根因是**颜色被映射了两次**：

```
1. Ui.applyTheme() 把 Ui.CARD 从 0xFFFFFFFF 改成深色卡片色 0xFF1E1B28
2. Ui.round() 又对这个值调 Theme.adapt()
3. adapt 看到 0xFF1E1B28 亮度很低 → 判定为"深色文字" → 翻成浅色 0xFFF2EEF8
结果：卡片变浅、正文变深，正文落在浅卡片上就不可见
```

实测复现（脚本验算）：

| | 第一步 | 第二步 | 白卡片上的正文对比度 |
|---|---|---|---|
| 卡片 | `0xFFFFFFFF` → `0xFF1E1B28` | → `0xFFF2EEF8` | |
| 正文 | `0xFF1E1B2E` → `0xFFF2EEF8` | → `0xFF262232` | **13.53**（看着"合格"，但颜色全错位了）|

**修法：单次映射原则。** 所有令牌恢复成 `final` 的浅色原值，
`Theme.adapt()` 成为唯一的映射出口。`applyTheme()` 留空以兼容调用点。

顺带把 35 处"直接使用令牌、绕过工厂"的地方
（`setBackgroundColor(Ui.BG)` 这类）显式包上 `Theme.adapt()`。

### 二、彩色按钮上的白字也被映射成深色

单次映射之后暴露的新问题：`0xFFFFFFFF` 有两种含义 ——
当底色时该变深，当文字时（彩色按钮上的白字）必须保持白。
光看颜色值分不出来。

**修法：加 `Theme.adaptText()`**，由调用方（`Ui.tv` / `Ui.pill`）明确声明"这是文字"。
不透明的纯白直接原样返回。

### 三、"跟随环境光"不自动切换

查下来是两件事：

1. **当时选的是「始终浅色」**（我上一轮验证完停在这个模式）。
   这个模式按设计就不注册传感器，所以不切换是对的。
2. 但确实有个真缺陷：**冷启动时 AUTO 模式只用"上次记住的结论"**，
   用户从被窝走到窗边要等传感器的 3 秒限流窗口才纠正。

**修法**：`onResume` 里异步读一次光校正（`Theme.syncAutoFromSensor`），
拿到结果立刻 `recreate()`。读光必须放后台线程 —— 最多阻塞 900ms。

### 四、深色下主按钮的白字对比度不够

调色板调整后，主按钮渐变上的白字对比度只有 **4.23**（低于 4.5）。

**修法**：给按钮渐变单独一个入口 `adaptButtonGradient()`，
深色下固定用 `0xFF6D28D9 → 0xFF7C3AED`，白字最低 **5.70**，达标。
按钮是"亮底 + 白字"的组合，不能走通用彩色的"提亮"规则。

### 最终实测（真机截屏采样像素）

| 检查项 | 结果 |
|---|---|
| 页面背景 | `#1E1B27` |
| 卡片底色 | `#1E1B27`（不再变白）|
| 大片白底 | **无**（逐行扫描，白色像素全是文字/图标）|
| 白色像素占比 | 10%（正常）|

对比度：卡片文字 **16/16 全部 ≥ 4.79**，主按钮白字 **5.70**。

### 教训

这三件事里，**没有一件是靠"看着像"能发现的**。
两次都是写完脚本验算对比度、或者采样真实像素，才把问题抓出来。
第一版"看上去改完了"其实是坏的。
