# 一像素悬浮窗保活

## 解决的问题

**"必须打开 App 才能收到通知和弹窗"**。

之前的保活方案是「前台服务 + 常驻通知」，它能让**进程活着**，
但保不住**网络回调**。实测现象：

| 接单端状态 | 端口响应 |
|---|---|
| 前台 | 200 |
| 后台（仅前台通知） | **000 超时** |
| 后台（+ 一像素窗） | **200** |

注意进程并没有被杀 —— 切回前台立刻恢复。是系统把它判定为
"后台受限"，冻结了网络活动。

## 为什么一像素窗有效

Android 对"屏幕上还有可见窗口的进程"给更高的进程优先级，
不会把它当作纯后台应用去冻结。

所以关键不是"像素有多小"，而是**"屏幕上有没有一个窗口"**。

## 实现（core/PixelKeeper.java）

```java
1 × 1 像素
alpha      = 0        完全透明
x = -1, y = -1        挪到屏幕外一点
FLAG_NOT_FOCUSABLE    不抢焦点
FLAG_NOT_TOUCHABLE    点不到、不挡操作
```

三个刻意选择：

**1. 用真的 TextView，不是空 View。**
某些 ROM 会把"没有内容的 View"优化掉或不认为它在绘制，那样起不到保活作用。
这里放一个空字符串 TextView，确保它真的参与绘制。

**2. 每分钟自愈。**
有些 ROM 会回收"不可见"的悬浮窗。定时检查 `getWindowToken() == null`
就重新 addView。这个定时器本身也顺带让进程保持活跃。

**3. 不做"略微可见"。**
考虑过 1 像素带点颜色。不这么做 —— 情侣 App 屏幕边缘常驻一个小点会让人困惑。
完全透明 + 不可触摸是最不打扰的形态。

## 权限

需要 `SYSTEM_ALERT_WINDOW`（显示在其他应用上层），**必须用户手动授权**，
不能静默请求。没授权时 `start()` 返回 false，自动退回纯前台服务模式。

设置入口：「我」页 → 🔋 后台保活 → **屏幕边缘常驻（更可靠）**

没授权时会显示一个橙色提示条，点它直接跳授权页。

## 实测数据（vivo V2502A / Android 17）

接单端切到后台，持续探测 8765 端口：

```
后台 +8s:  200
后台 +16s: 200
后台 +24s: 200
后台 +32s: 200
后台 +40s: 200
后台 +48s: 200
后台 +56s: 200
后台 +64s: 200
后台 +72s: 200
后台 +80s: 200
```

**10/10 全部 200，共 80 秒。** 对比开启之前（后台 +8s 就已经 000）。

## 局限

- **不能替代系统级设置。** vivo/小米的「自启动」「后台高耗电」限制仍然有效，
  一像素窗能提高存活率，但用户把 App 加进"深度睡眠"名单时还是会断。
- **耗电**：一个透明窗口 + 每分钟一次定时器，实测影响很小，
  但不是零。所以做成了开关，用户自己决定。
- **某些 ROM 可能直接忽略**（尤其国产深度定制系统）。
  这种情况只能靠用户手动放宽后台限制。

# 远程震动（叫一下猫猫）

## 问题

用户反馈"震动功能暂时不可用"。

## 根因

`RecvScreen.buzzCat()` **只走直连**：

```java
Net.post(catHost, fport, Protocol.PATH_BUZZ, ...)   // 异地必然失败
```

异地时 `peer_host` 那个 IP 根本连不上，于是永远发不出去。

## 修法

和订单一样按优先级：**直连 → 中转**

```java
boolean ok = false;
if (catHost != null && port > 0) {
    ok = Protocol.isOk(Net.post(catHost, port, PATH_BUZZ, buzzBody, 3000));
}
if (!ok && Relay.enabled(act)) {
    ok = Relay.publish(act, Protocol.ROLE_RECV, buzzBody, 8000);
}
```

同时改进了提示：都没配对时直接告诉用户"去连接方式里配一次"，
而不是含糊地说"还不知道猫猫的地址"。

## 实测

中转链路（JVM，用 App 里同一份代码）：

```
buzz payload = {"type":"buzz","role":"recv","reason":"张老师急着找你！！","ms":1500,...}
发送 = true
收到 type=buzz  ms=1500  reason=张老师急着找你！！
PASS 震动消息可经中转送达
```

真机部分：系统震动接口正常（30/55/100/300ms 全部 OK），
权限 `VIBRATE` 在 APK 里确认存在。

> 坦白：**"点单端在后台时收到远程震动"这一条我没能在真机上端到端验证**。
> 因为单机测试时点单端必然退到后台，而震动是瞬时效果，
> 我无法从 dump 里确认它真的震了。需要你两台手机实测。
