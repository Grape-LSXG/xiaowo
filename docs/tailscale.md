# 异地联机：Tailscale 方案

> 结论先行：**Tailscale 能用，App 几乎不用改代码。**
> 它是虚拟局域网，给每台设备一个固定的 `100.x.y.z` 地址，
> 所以在 App 里按普通 IP 填就行，不用 https、不用隧道、不用中转服务器。

---

## 1. 为什么放弃 SakuraFrp

实测结论，不是猜测：

```bash
$ curl http://frp-cat.com:29185/ping
HTTP/1.1 501
您正试图使用 HTTP 协议访问此隧道 …… 执行机房的内容合规要求
和有关部门的管控规定 …… 请使用 HTTPS 后访问此隧道
```

SakuraFrp 为满足机房合规要求，**拦截明文 HTTP**。
而我们的隧道是 TCP 类型，TCP 隧道只做端口转发、不负责 TLS 握手，
所以「改成 https:// 访问」也走不通（`Connection refused`）。

要让它工作，得把隧道改成 HTTP/HTTPS 类型 —— 那就得重新配域名和证书，
对「两个人的小工具」来说完全不值得。Tailscale 绕开了整件事。

---

## 2. 怎么做（两台手机各一次）

1. **两台手机都装 Tailscale**，并**登录同一个账号**（或同一个 tailnet）。
2. 打开开关，看到 **Connected**。
3. 在**张老师（接单端）**手机上打开小窝 → 首页状态卡会显示：

   ```
   🛰 Tailscale：100.94.232.43:8765　点一下复制
   ```

   点一下就复制到剪贴板，直接发给猫猫。

4. 在**猫猫（点单端）**手机上打开小窝 → 点右上角 `⇄ 连接`，
   把刚才那个地址粘进去（形如 `100.94.232.43:8765`），保存。

> 关键点：**不要加 `https://`**。Tailscale 是虚拟内网，明文 HTTP 就是通的。
> App 里的输入框已经会识别：只有以 `https://` 开头的地址才走 HTTPS。

## 3. 实测记录（2026-10-22，vivo V2502A / Android 17）

### 3.1 Tailscale 入站通路 —— 通过

这是整个方案唯一可能不成立的前提：**手机上的服务能不能被外部连进来？**

```bash
$ curl http://100.94.232.43:8765/ping
{"ok":true,"role":"recv","port":8765}      HTTP 200，4ms
```

**能。** Tailscale 的虚拟网卡会把入站连接正常交给 App 的监听端口，
不需要 root，也不需要额外配置。

### 3.2 后台保活 —— 必须开

接单端退到后台后，端口会不会继续应答：

| 接单端状态 | `/ping` 结果 |
|---|---|
| 前台 | 200 |
| 后台 + 保活**开** | 200（连续测 40 秒稳定） |
| 后台 + 保活**关** | **000 超时** |

保活卡上写的就是这个结论。**异地联机必须打开「🔋 后台保活」**，
代价只是通知栏多一条常驻通知。

v2.1 起还给 `KeepAlive` 加了 `PARTIAL_WAKE_LOCK`（只保 CPU、不亮屏），
因为只挂前台通知时，机器一进深睡端口就不再应答。

### 3.3 一个必须讲清楚的测试局限

**同一台手机无法完整模拟两台手机的场景。**

Android 前台槽位只有一个。当点单端在前台时，接单端必然退到后台；
而实测表明，接单端在后台超过一定时间后，vivo 会冻结它 ——
这时**即使保活开着、WakeLock 持有、通知还在**，端口仍然 000。

这一点已经隔离验证过，不是 Tailscale 的问题：

```
点单端在前台 → curl 100.94.232.43:8765/ping → 000
把接单端切到前台 → 同一个 URL → 200
```

进程根本没被杀（切回前台立即恢复），只是被冻结了。

**所以「单机同时开着两个 App 互相点单」是测不出真实效果的。**
真正的验证需要：两个 App 分别装在两台手机上，各自都是前台/正常后台。

## 4. 猫猫和张老师各自要做什么

**张老师（接单端）**
- 装 Tailscale 并登录
- 打开小窝 → 点「开始」接单
- 打开「我 → 🔋 后台保活 → 保持后台运行」
- 把 `🛰 Tailscale：100.x.y.z:8765` 复制发给猫猫

**猫猫（点单端）**
- 装 Tailscale 并登录同一个账号
- 打开小窝 → `⇄ 连接` → 粘贴 `100.x.y.z:8765` → 保存
- 正常点单

> 同一个 Wi-Fi 下可以什么都不填，App 会 UDP 广播自动发现，
> Tailscale 那套只在异地时才需要。

## 5. 代码改了什么（v2.0 → v2.2）

| 文件 | 改动 |
|---|---|
| `core/Net.java` | 新增 `tailscaleIpv4()` / `isTailscaleIp()`，`localIpv4()` 优先返回 `100.64.0.0/10` 地址 |
| `ui/RecvScreen.java` | 状态卡新增 `🛰 Tailscale：地址:端口　点一下复制` 一行；`updateStatus` 联动刷新；订单按 `id` 去重 |
| `ui/OrderScreen.java` | 连接框文案改为 Tailscale 优先；下单失败时**重试一次**（超时不等于没送到，重试带同一个 id，接单端去重） |
| `ui/KeepAliveCard.java` | 说明文字改成实测结论 |
| `core/KeepAlive.java` | 增加 `PARTIAL_WAKE_LOCK` 的获取/释放 |

`100.64.0.0/10` 是 CGNAT 保留段，只会属于 Tailscale，
所以用它来判断「本机有没有 Tailscale 地址」是可靠的。

## 6. 还能怎么改进

- **超时提示更准**：现在失败统一报「没连上」，
  但「对方在后台被冻结」和「地址填错了」是两回事。
  可以探测一次再给建议（提示对方去看保活/电池设置）。
- **vivo 后台限制**：`设置 → 电池 → 允许后台活动`、
  `自启动`，这两个开关对国产 ROM 比代码更有效，已写进保活卡的提示。
- **Tailscale 掉线兜底**：Tailscale 断开时地址仍在（只是连不通），
  可以考虑定时 ping 一下，在 UI 上显示「Tailscale 已断开」。

---

## 7. 一句话总结

> Tailscale 这条路是通的（入站 200 实测过）。
> 需要打开后台保活，且**必须两台手机分别测试** ——
> 单机上一个 App 在前台时，另一个必然被冻结，这是测试环境的限制。
